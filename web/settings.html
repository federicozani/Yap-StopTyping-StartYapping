Test & diagnostics
If Yap isn’t working, run these checks to see exactly where the problem is. Each test is independent. Nearly every first-run problem is one of the three macOS permissions below not being switched on — open Not working? under a failing test for the exact steps.

1 · Microphone

Records about 3 seconds from your selected microphone (Default (system)) and checks that sound comes through.
Not tested yet.
▶ Not working? Fix the Microphone permission Checking…

Yap needs Microphone access to hear you. macOS asks for it once, the first time you record. If that prompt was dismissed or never appeared, Yap records pure silence and every button does nothing.

  1. Click Open Microphone settings below. (By hand: menu → System Settings → Privacy & Security → Microphone.)
  2. Find Yap in the list and turn its switch on.
  3. Come back here and run the test again.

No Yap in the list? It only appears after Yap has tried to record at least once — press a voice shortcut, then look again. If the switch is already on but the test still fails, pick a different input under Recording, or raise the input volume.

2 · Recording hotkey

Checks that Yap can see your shortcut (needs Input Monitoring). After you press Test hotkey, hold Right Option (⌥) and tap an arrow for a voice button.
Not tested yet.
▶ Not working? Fix the Input Monitoring permission Checking…

Yap needs Input Monitoring to notice that you’re holding the shortcut. Without it Yap runs and looks fine, but pressing ⌥ + an arrow does nothing at all.

  1. Click Open Input Monitoring settings below. (By hand: menu → System Settings → Privacy & Security → Input Monitoring.)
  2. Find Yap in the list and turn its switch on.
  3. Quit and reopen Yap. This one only takes effect after a restart — use the button below.
  4. Reopen Settings and run the test again.

Already switched on but still failing? Turn it off and back on, then restart Yap — macOS keeps a stale entry after an app is updated or moved.

3 · Pasting into apps

Checks that Yap is allowed to drop its result where your cursor is (needs Accessibility). This also powers the text Rewrite shortcut.
Not tested yet.
▶ Not working? Fix the Accessibility permission Checking…

Yap pastes by pressing ⌘V for you, and macOS only lets apps trusted for Accessibility do that. Without it, Yap records and transcribes correctly but nothing ever lands in your document — and the ⌘⌥ Rewrite shortcut won’t fire.

  1. Click Open Accessibility settings below. (By hand: menu → System Settings → Privacy & Security → Accessibility.)
  2. Find Yap in the list and turn its switch on.
  3. Come back here and run the test again — no restart needed, Yap picks this one up within a few seconds.

Text still not appearing with Accessibility on? Your transcript is always copied to the clipboard as well, so you can press ⌘V yourself. Some apps also refuse pasted input in password fields.

4 · AI connection

Sends one tiny request to your selected provider and model using the saved key, to confirm the key and model work.
Not tested yet.
▶ Not working? Fix the connection

This one isn’t a macOS permission — it’s your API key, your model choice, or the network. The message above the fold says which.

  1. Key rejected (401 / 403): go to Provider & model and paste the key again — it’s easy to copy a space or half the string.
  2. Model not available (404): pick a different model under Provider & model. Not every key can use every model.
  3. Rate limited (429): wait a minute and test again.
  4. Couldn’t reach the provider: check your internet connection, and any VPN or firewall that might block it.

Your privacy

Yap records your microphone only while you hold the shortcut. That audio (and, for the Rewrite button, the text you have selected) is sent over an encrypted HTTPS connection to the provider you choose — Google Gemini or OpenAI — which turns it into finished text that Yap pastes back. Nothing else leaves your Mac: no account, no analytics, no tracking.

You bring your own API key. It is stored only in ~/.yap/config.json on this Mac and is sent solely to your chosen provider. Your transcripts are never written to Yap’s log.

Audio and text you send are processed by that provider under their terms — see Google’s and OpenAI’s privacy policies for how they handle API data.
